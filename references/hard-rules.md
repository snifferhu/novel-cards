# 硬规则（hard-rules.md）

novel-cards skill 的所有行为准则集中于此。规则分为**不可变硬规则**（AI 必须遵守）
与**提案-确认流程**（AI 与用户交互的形态）。v1.0 在保留 v0.x 有效旧规则的基础上，
追加了数据分层、审计只读、五感公理、黑盒建模、pose 插槽优先级、注册前置、素材合规
等 v1.0 新硬规则。

## 规则一览

| # | 规则 | 强度 |
|---|---|---|
| 1 | AI 绝不直接 `edit` / `write` 使用方工程的卡片、图谱、反思卡、练习稿文件 | 硬性 |
| 2 | AI 回写卡片一律以**完整 Markdown 提案**输出到对话，图谱以完整 HTML 提案输出，反思卡以完整五段结构输出，等用户确认后由用户落盘 | 硬性 |
| 3 | 伏笔卡（`type: foreshadow`）必须关联 `payoff_chapter` **或** 显式标注 `status: unresolved`；二者皆缺视为非法 | 硬性 |
| 4 | 暗线卡（`type: darklayer`）使用独立命名空间（`cards/darklayer/`），不混入主书人物链；与主书人物的引用只通过显式字段 `references_to_main` 串接 | 硬性 |
| 5 | 所有卡片 frontmatter 至少含 `id` / `type` / `status` / `created` / `updated` 五字段 | 硬性 |
| 6 | 双端兼容：`SKILL.md` frontmatter 只允许 `name` / `description` / `license` 三键 | 硬性（针对 skill 本身，不是卡片） |
| 7 | 关系图谱 HTML 存放于使用方工程的 `graph/` 目录，**不进入** `cards/`；卡片正文可引用图谱文件，图谱本身无 frontmatter，不被视为卡片 | 硬性 |
| 8 | 动线卡（`type: timeline`）必须通过 `track` 字段声明追踪对象类型（`character` / `item` / `faction` / `place` / `other` / 已注册的自定义类型），`target` 指向具体对象 id | 硬性 |
| 9 | 反思卡（`type: reflection`）存放于 `reflections/` 目录，正文必须含 `stuck` / `shone` / `why` / `insights` / `action_items` 五个二级标题；`action_items` 是唯一把新认知写回卡片的入口 | 硬性 |
| 10 | 所有新素材（首次入库的题材 / 口述灵感 / 反思卡反哺回来的素材）在写入 `cards/` 前必须过通胀过滤器三问；`Q3`（独家洞察）是否决项，无独家洞察一律进 `drafts/practice/` | 硬性 |
| 11 | **四层数据分层铁律**：`.md` 是人类主编辑载体（业务源头）、`.json` 是机器索引/图森林真值、`.yaml` 是静态配置白名单、`.html` 是纯展示投影；html MUST 由 json 重生成，不存业务逻辑 | 硬性（v1.0 新增） |
| 12 | **审计类技能只读**：`nc-校阅` / `nc-节奏` / `nc-守卫` MUST 只输出意见，绝不自动修改、删除任何文稿或卡片内容；所有发现以「建议」形式呈现，由作者自行决定是否采纳并手动修改 | 硬性（v1.0 新增） |
| 13 | **五感公理**：感知动线的根 MUST 落在人类原生五感之一（视觉/听觉/嗅觉/味觉/触觉）；玄幻衍生感知 SHALL 建模为对应五感的子标签变体，MUST NOT 新增脱离五感底层的独立感知大类 | 硬性（v1.0 新增） |
| 14 | **道具黑盒三层**：`item` 卡 SHALL 支持物理层/感知层/抽象非感知层三层内部结构；默认黑盒模式由 skill 自动拆解，高级模式才允许手动调整感知 track 绑定 | 硬性（v1.0 新增） |
| 15 | **pose 插槽三级优先级**：P1 桥段本地手动覆写 > P2 当前时间锚点快照状态自动填充 > P3 pose 默认兜底；填充后 MUST 跑 `extra_constraint` 校验，冲突进入 `nc-校阅` 意见，不自动改文字 | 硬性（v1.0 新增） |
| 16 | **注册前置**：新增自定义卡片类型、动线 track 标签或动向卡人格基线原型枚举取值 MUST 先经 `nc-注册` 写入 registry 白名单再建卡 | 硬性（v1.0 新增） |
| 17 | **素材合规 fail-closed**：网页 URL 抓取 MUST 先校验目标站点 robots.txt，禁止路径直接拦截不请求页面；不尝试绕过反爬/登录/动态渲染；任何不确定情况按「禁止」处理终止；抓取成功必附版权提醒 | 硬性（v1.0 新增） |
| 18 | **actor 与 item 区分**：拥有独立意志主动行动的道具 SHALL 建模为 `actor`（标签 `object-spirit`），原 `item` 卡保留物理本体描述，两卡通过 `cross_ref` 互相引用 | 硬性（v1.0 新增） |
| 19 | **跨动线同步走 module**：跨动线同步变化 MUST 走 module 积木模块，禁止在正文或动线卡里零散写联动 | 硬性（v1.0 新增） |
| 20 | **长线四方对齐**：长线道具/感官爆点 MUST 满足伏笔 `fs-` + 动线 `tl-` 节点 + 模块 `md-` + 词频 `lx-` 提前 ≥8 章预埋，缺一即视为预埋不完整 | 硬性（v1.0 新增） |
| 21 | **设定卡检索容错与差异归档**：更新已有卡前 MUST 模糊匹配并返回全部候选（含同物异名/拼写近似），由作者确认是哪一张；当新旧内容存在实质差异时 MUST NOT 原地覆盖，先把旧版本快照到 `history/<card-id>/<date>.md` 再出新版提案 | 硬性（v1.0 新增） |
| 22 | **暗线 = 整条明面叙事的隐性逻辑**：暗线卡（`dk-`）MUST NOT 被窄化为「仅指代角色」；它表达的是读者需自行推敲的隐秘逻辑，可挂接设定 / 桥段 / 角色 / 道具 / 势力等多类主书对象（经 `references_to_main` 混合引用）；`implicit_kind` 标注主导类型（setting/plot/character/mixed） | 硬性（v1.0 新增） |
| 23 | **自动成稿走提案制 + 作者校阅**：`nc-成稿`(nc-draft) 读取已备卡片自动生成正文初稿时，MUST 以完整 Markdown 提案输出到对话、标注目标路径，由作者校阅调整后落盘；MUST NOT 直接写入 `manuscript/`。篇幅档位由 `--length short/mid/long` 控制，对应不同生成密度 | 硬性（v1.0 新增） |
| 24 | **研判/编排只出建议与计划，绝不静默改卡**：`nc-研判`(nc-analyze) MUST 只输出结构化分析报告 + 方案 A/B/C，绝不直接改动任何 cards/素材；`nc-编排`(nc-compose) MUST 先生成 compose_plan 交作者逐条审核，执行前 MUST 前置跑 `nc-校阅` 扫冲突，遇红色冲突暂停退回计划页，全程禁止静默修改 | 硬性（v1.0 新增） |
| 25 | **更名先预览后替换且不动原始素材**：`nc-更名`(nc-rename) MUST 先输出【替换预览清单】（每处文件 + 原文片段），作者确认批准后才批量写入；MUST NOT 修改 `res/` 原始素材文件夹内容，MUST NOT 改动正文描写文本里的自然口语称呼，只处理卡片注册的标识符 | 硬性（v1.0 新增） |
| 26 | **动向每次变动必须绑定已存在桥段**：`character_tendency`（`tend-`）卡的 `history[]` 每一条 MUST 绑定一个**已存在**的桥段卡（`trigger_plot` 引用真实 `pp-*` id）作为推手事件，禁止无事件推手的凭空变性格；该卡依附角色（`target_role` 引用 `ac-*`），MUST NOT 替代角色基础卡 | 硬性（v1.0 新增） |

## 规则 1 & 2：提案制详解

### AI 输出格式

AI 在对话中输出卡片提案时，**必须**：

1. **完整可读**：一份提案 = 一份完整卡片 Markdown（含 frontmatter + 正文）
2. **代码块包裹**：用 ``` 代码块包裹，便于用户复制到编辑器
3. **明确目标路径**：在代码块前说明该卡片应保存到何处，例如
   `→ 建议保存路径：cards/characters/ac-frog-lead.md`
4. **不承诺落盘**：**禁止**在提案末尾写"我已写入文件"、"卡片已保存到..."
   这类措辞；应写"请确认后保存到上述路径"

### 用户确认方式

用户在确认提案时可能的输入形式：

- `保存` / `OK` / `确认` → 用户自行复制代码块到编辑器并保存
- `改一下 <字段>` → AI 重新输出修改后的提案
- `不要` / `pass` → AI 记录该提案被拒绝，不做进一步动作

### 禁止措辞（AI 输出时）

- ❌ "我已保存该卡片到 ..."
- ❌ "文件已写入"
- ❌ "接下来我会创建 ..."（针对卡片 / 反思卡 / 图谱文件）
- ✅ "建议保存到 ..."
- ✅ "请确认后复制到 ..."
- ✅ "以下是提案，未落盘"

## 规则 3：伏笔卡合法组合

| `status` | `payoff_chapter` | 合法性 | 说明 |
|---|---|---|---|
| `unresolved` | 缺失 | ✅ 合法 | 明确标记为未回收伏笔 |
| `unresolved` | 缺失或存在 | ✅ 合法 | 若已有回收章节但仍保持 unresolved，需 `notes` 说明理由 |
| `resolved` | `chapter-XX` 或 `chapter-XX.md` | ✅ 合法 | 已回收，指向具体章节 |
| `resolved` | 缺失 | ❌ **非法** | 已回收却无回收章节，逻辑不自洽 |
| 其他 | 缺失 | ❌ **非法** | 非法状态值或缺失状态 |

**校验逻辑（伪代码）**：

```python
def validate_foreshadow(fm):
    status = fm.get('status')
    payoff = fm.get('payoff_chapter')
    if status == 'unresolved':
        return True
    if status == 'resolved' and payoff:
        return True
    return False
```

## 规则 4：暗线边界表

| 允许 | 禁止 |
|---|---|
| `cards/darklayer/` 下 `dk-*` 命名的卡片 | 把 `dk-*` id 放入 `cards/characters/` 等主书目录 |
| 暗线卡通过 `references_to_main` 显式引用主书 id | 主书人物卡通过任何字段引用 `dk-*` id |
| 主书人物卡可通过 `aliases` / `disguises` 文本暗示暗线身份 | 主书人物卡通过 `character_id: dk-*` 类字段直接链接 |
| 暗线卡正文可详细描写暗线情节 | 主书卡正文大段引用暗线细节 |

**为什么这么设计**：暗线卡的存在本身是对读者的隐藏信息；如果主书卡通过字段
反向链接暗线，工具链检索时就会把暗线泄漏到主书上下文，破坏"暗"的语义。

## 规则 5：五字段检查法

用户或 CI 可用以下命令检查现有卡片是否合规：

```bash
# 列出缺少任一必备字段的卡片（cards/ 与 reflections/ 都适用）
grep -rLE '^(id|type|status|created|updated):' cards/ reflections/ --include='*.md'
```

或按类型分目录检查：

```bash
for dir in cards/*/ reflections/; do
  grep -rLE '^(id|type|status|created|updated):' "$dir" --include='*.md'
done
```

**空行处理**：`created` / `updated` 值为空应视为缺失。ISO 8601 建议格式：
`YYYY-MM-DD` 或 `YYYY-MM-DDTHH:MM:SSZ`。

## 规则 7：图谱与卡片分离

**背景**：Markdown 表格难以表达多节点、多类型的复杂关系（尤其是
"暗示关系"、"多角色三角"、"跨势力协作"等）。当关系密度超过表格可表达
范围时，使用 HTML + SVG 图谱。

**允许**：
- 图谱 HTML 存放于 `<consumer-root>/graph/`
- 卡片正文写 `见 graph/tl-xxx-graph.html` 提示
- 同一动线可对应一份图谱，也可对应多份（不同视角）

**禁止**：
- 图谱放入 `cards/` 目录
- 图谱文件带 frontmatter（YAML 前置元数据块）
- 卡片通过 `type: timeline` 直接内嵌 SVG 代码（应放 `graph/` 独立文件）
- 图谱通过 skill 硬规则校验（图谱不受五字段约束）

## 规则 8：动线卡 track 分类

动线卡通过 `track` 字段显式分类，便于检索：

| `track` 值 | `target` 指向 | 示例 |
|---|---|---|
| `character` | `ac-*` id | `tl-hairstyle` |
| `item` | `it-*` id | `tl-bronze-key` |
| `faction` | `fa-*` id | `tl-shenzhi-rise` |
| `place` | `sc-*` id | `tl-shenzhi-hq` |
| `other` | 无固定类型 id | `tl-winter-season`（跨对象主题线） |
| 自定义类型 | 经 `nc-注册` 写入 `registry/tracks-registry.yaml` 白名单 | `temperature-field` |

`target` 在 `track: other` 时可省略或填写自由字符串；其他取值必须指向
对应类型的有效卡片 id。自定义 track MUST 先经 `nc-注册` 注册（规则 16）。

## 规则 9：反思卡结构

**背景**：反思卡用于把「写作过程本身的经验」显式沉淀下来，通过反哺机制
让下一篇文章继承上一篇文章的所有新认知。反思卡是**元卡片**，不是小说
内容的一部分，所以放在 `reflections/` 独立目录。

**允许**：
- 位置：`reflections/<chapter-id>.md`
- id：`rf-<chapter-id>`（例：`rf-chapter-050`）
- 正文五个二级标题按顺序出现：`stuck` / `shone` / `why` / `insights` /
  `action_items`
- `action_items` 使用 markdown 任务列表 `- [ ] <verb> <target-id-or-path>：<内容>`

**禁止**：
- 反思卡放入 `cards/` 目录
- 缺 `action_items` 段（即使本次没有反哺，也要留空段并写 `暂无`）
- `action_items` 出现模糊动作（如「优化人物刻画」「完善世界观」）
- 反思卡正文直接引用 `dk-*` 暗线 id（避免暗线泄漏到复盘上下文中）

**校验逻辑（伪代码）**：

```python
def validate_reflection(fm, body):
    if fm.get('type') != 'reflection':
        return False
    if not fm.get('chapter'):
        return False
    required_sections = ['stuck', 'shone', 'why', 'insights', 'action_items']
    for sec in required_sections:
        if f'## ' + sec not in body.lower():
            return False
    return True
```

**反哺动作格式约定**：

```markdown
- [ ] 更新 `cards/characters/ac-frog-lead.md`：把「表面身份」字段扩展为「三层身份」
- [ ] 新建 `cards/foreshadow/fs-orphan-letter.md`：埋第 50 章发现的信件伏笔
- [ ] 更新 `graph/tl-hairstyle-graph.html`：补 `ac-su-ye` ↔ `fa-shenzhi-hui` 的暗示边
- [ ] 补素材：需要用户口述「孤儿院失踪事件」背后的第三层真相
```

**action_items 处理原则**：

- **逐条提案**：一条 action_item 单独出反哺提案，不批量静默执行
- **可回滚**：描述「改成什么」而非「删除什么」
- **可跳过**：用户可以跳过任何一条 action_item，AI 记录为 `skip`
- **完成后关闭**：全部处理完毕后，反思卡 `status` 可以从 `draft` 改为
  `closed`（同样走提案）

## 规则 10：通胀过滤器 gate

**背景**：素材是稀缺资源。不过滤的后果是素材库膨胀但产出效率不变，
写作选题时面对一堆同质化素材无从下手。过滤器给每个新素材一个明确
状态标签：「正式排期」或「练习稿」，两类都在库但只有一类进排期。

v1.0 中，三问逻辑已并入 `nc-素材` 入库前的自动 gate；同时保留手动
`nc-过滤` 复检能力（对已入库素材或特定素材做二次审查）。

**触发时机**：

| 场景 | 是否触发 |
|---|---|
| `nc-素材` 录入新素材（本地/纯文本/URL） | ✅ 自动 gate（入库前必过） |
| 反思卡反哺回来的新素材 | ✅ 必须过 |
| 用户明确说「这个先当练习稿」 | ❌ 跳过（用户已判定） |
| 更新已有卡片 | ❌ 不过（不是新素材） |
| 用户说「nc-过滤 一下」 | ✅ 手动复检 |

**三问**：

| 问题 | 判定要点 |
|---|---|
| Q1. 公共领域性 | 这个题材是否是公共领域人人都能讨论的？是 → 需靠角度差异化；否 → 自带排他性 |
| Q2. 三个月复刻性 | 如果我不做，三个月后会不会有别人用同样角度做出来？是 → 角度不新鲜；否 → 稀缺 |
| Q3. 独家洞察 | 我的角度里有没有只有我知道、只有我能提供的特殊经验或洞察？ |

**判定矩阵**：

| Q1 | Q2 | Q3 | 判定 | 去向 |
|---|---|---|---|---|
| 是 | 是 | 否 | ❌ 练习稿 | `drafts/practice/` |
| 是 | 是 | 是 | ⚠️ 需强化独家洞察 | 用户决定 |
| 是 | 否 | 是 | ✅ 可排期 | 素材池 |
| 否 | 是 | 否 | ⚠️ 门槛题材但无洞察 | 补洞察再评估 |
| 否 | 是 | 是 | ✅ 可排期 | 素材池 |
| 否 | 否 | 是 | ✅ 强推荐 | 优先排期 |
| 否 | 否 | 否 | ⚠️ 门槛在但无洞察 | 补洞察 |
| **任意** | **任意** | **否** | ❌ **练习稿**（Q3 是否决项） | `drafts/practice/` |

**Q3 是否决项**：没有独家洞察的素材，无论题材多小众、多稀缺，都只能是
练习稿。因为写作最终比拼的是「你能提供的独家价值」，而不是「题材本身」。

**什么不算独家洞察**（避免自我欺骗）：

- 「我比别人更努力」— 努力不产生独家性
- 「我文笔更好」— 技法可训练，不构成护城河
- 「这个题材我很喜欢」— 喜好不等于稀缺
- 「我知道一些别人不知道的事」但无出处、无验证 — 需要具体证据

**输出格式（提案，不落盘）**：

```
【通胀过滤器提案】素材：<摘要>

Q1 公共领域性：<是/否> — <一句话理由>
Q2 三个月复刻性：<是/否> — <一句话理由>
Q3 独家洞察：<有/无> — <一句话理由，若有需指出独家洞察形态>

判定：<练习稿 / 需强化 / 可排期 / 强推荐>
去向：<drafts/practice/ 或 素材池>

请确认：
(1) 同意此判定
(2) 补充独家洞察后重新评估
(3) 覆盖判定（用户强制排期，AI 需记录理由）
```

**用户覆盖判定**：过滤器是辅助不是决策，用户可覆盖。覆盖时 AI 需在
练习稿文件顶部记录覆盖理由（三行以内），便于日后复盘。

## 规则 11：四层数据分层铁律（v1.0 新增）

`.md` / `.json` / `.yaml` / `.html` 四层各司其职，职责边界不可越界：

- `.md`：人类主编辑载体，业务源头，可直接改
- `.json`：机器索引、图森林真值、数值索引，系统同步生成，优先经 nc- 指令改动
- `.yaml`：静态配置白名单，人工少量维护
- `.html`：纯展示投影，**MUST 由 `index/card-graph.json` 重生成**，不存业务逻辑

详见 `references/data-layering.md`。

## 规则 12：审计类技能只读（v1.0 新增）

`nc-校阅` / `nc-节奏` / `nc-守卫` 三个审计类技能 MUST 只输出意见，绝不自动修改、
删除任何文稿或卡片内容。所有发现以「建议」形式呈现，由作者自行决定是否采纳并
手动修改。这是审计技能的铁律，违反即破坏提案制边界。

## 规则 13：五感公理（v1.0 新增）

感知动线的根 MUST 落在人类原生五感之一：视觉 / 听觉 / 嗅觉 / 味觉 / 触觉
（温·压·痛·肌理）。玄幻衍生感知 SHALL 建模为对应五感的子标签变体，
MUST NOT 新增脱离五感底层的独立感知大类：

| 玄幻衍生感知 | 归入五感根 | 子标签形态 |
|---|---|---|
| 灵识/神念扫描 | 触觉 | 回声定位型探测（雷达·声呐） |
| 神视/天眼 | 视觉 | 延伸（穿透·望远·透视·多波段） |
| 灵嗅/辨息 | 嗅觉 | 超距高分率版 |
| 灵味/道韵尝感 | 味觉 | 抽象化 |
| 神魂刺痛/震颤 | 触觉 | 痛觉/压力投射到精神层面 |

非感知抽象动线（权力/秘密/记忆/欲望/宿命/张力/信任）与感知动线平行，互不侵占，
可通过 `nc-注册` 自由扩展。

## 规则 14：道具黑盒三层（v1.0 新增）

`item` 卡 SHALL 支持黑盒三层内部结构（物理层/感知层/抽象非感知层）。默认黑盒
模式：作者只自然描述道具，skill 自动拆解写入图森林；高级模式开关打开后展示三层
分区并允许手动调整感知 track 绑定。详见 `references/card-schema.md` item 章节。

## 规则 15：pose 插槽三级优先级（v1.0 新增）

pose 卡的插槽填充 MUST 遵循三级优先级：

1. **P1** 桥段本地手动覆写（`slot_override`）> 覆盖一切自动值
2. **P2** 当前时间锚点快照状态自动填充（默认，作者零填写，全章统一）
3. **P3** pose 默认兜底（`slot_default`，未绑定快照时，短篇常见）

填充后 MUST 跑 `extra_constraint` 校验（如"水下不可鼓腮"），冲突进入 `nc-校阅`
意见，不自动改文字。

## 规则 16：注册前置（v1.0 新增）

新增自定义卡片类型或动线 track 标签 MUST 先经 `nc-注册` 写入 registry 白名单
（`registry/types-registry.yaml` / `registry/tracks-registry.yaml`）再建卡。
未经注册的自定义 type / track 值视为 schema 违规。

动向卡（`character_tendency`）的可选字段 `baseline_prototype`（人格基线原型声明，
如自恋型人格的创作原型）同属本规则：取值 MUST 先经 `nc-注册` 写入
`registry/tendency-prototypes.yaml`（条目含 `label` / `description` /
`boundary_hints`）再写入卡提案；skill 不内置锁死枚举，安装骨架零预置。
未注册取值由 `nc-动向` 拦截。

## 规则 17：素材合规 fail-closed（v1.0 新增）

网页 URL 抓取 MUST 先校验目标站点 robots.txt：

- 禁止路径 → 直接拦截，不请求页面
- 不尝试绕过反爬/登录/动态渲染
- 任何不确定情况（robots 解析失败、网络异常）按「禁止」处理终止
- 抓取成功必附版权提醒
- 单次单链接，无批量采集能力，不商用

详见 `references/compliance.md`。

## 规则 18：actor 与 item 区分（v1.0 新增）

`actor` = 主动（能发起动作、有主观感知、有欲望动机）；`item` = 默认被动。
一旦道具拥有独立意志主动行动，SHALL 建模为 `actor`（标签 `object-spirit`），
原 `item` 卡保留物理本体描述，两卡通过 `cross_ref` 互相引用。

## 规则 19：跨动线同步走 module（v1.0 新增）

跨动线同步变化 MUST 走 module 积木模块（`trigger_map` 绑定多个 timeline 节点），
禁止在正文或动线卡里零散写联动。同一 module 可在不同章节复用，通过修改绑定的
动线节点产生不同效果。

## 规则 20：长线四方对齐（v1.0 新增）

长线道具/感官爆点 MUST 满足四方对齐：伏笔 `fs-` 卡、动线 `tl-` 节点、模块
`md-`、词频 `lx-` 卡提前 ≥8 章预埋，缺一即视为预埋不完整。`nc-校阅` 校验四方齐全。

## 规则 21：设定卡检索容错与差异归档（v1.0 新增）

作者口述/输入设定对象时拼写错误、记忆偏差、同物异名是常态。所有「更新已有卡」
类技能（含 `nc-检索` 触发的填充流程）MUST：

1. **多候选返回**：模糊匹配命中多个可能对应同一设定的记录时，列出全部候选
   （id + 关键差异），请作者确认；禁止 AI 自行拍板选定唯一候选后直接改写。
2. **无历史新建 / 有历史填充**：检索不到 → 走新建；命中 → 复用 id 做内容填充。
3. **实质差异先归档**：新旧内容有实质差异（非纯笔误）时，先把旧版本复制到
   `history/<card-id>/<updated-date>.md`（只读快照），再出新版提案；纯笔误/格式
   修正可直接出更新提案并注明「仅修正 X」。

该规则对全部卡类型生效，保证任意设定变更可回溯、可回滚。

## 规则 22：暗线 = 整条明面叙事的隐性逻辑（v1.0 新增）

暗线卡 MUST NOT 被窄化为「仅指代角色」。它表达的是**读者需自行推敲的隐秘逻辑**，
可以是隐秘设定、桥段真实因果、角色隐藏动机链或混合。一张暗线卡可通过
`references_to_main` 混合挂接多类主书对象（`ac-` / `pp-` / `it-` / `fa-` / `sc-`）。
`implicit_kind` 字段标注主导类型（`setting` / `plot` / `character` / `mixed`，默认
`mixed`）。判断标准：读者读完全文回看能发现「原来如此」的那条暗逻辑。

## 规则 23：自动成稿走提案制 + 作者校阅（v1.0 新增）

`nc-成稿`(nc-draft) 读取已备好的设定 / 桥段 / 大纲 / 暗线 / 角色等卡片，按
`--length short/mid/long` 控制篇幅档位，自动生成正文初稿。MUST：

- 以完整 Markdown 提案输出到对话，标注目标路径 `manuscript/chapter-*.md`
- 由作者校阅、调整后自行落盘；MUST NOT 直接写入 `manuscript/`
- 篇幅档位语义：`short`（精简骨架，约 1/3 篇幅）/ `mid`（标准，默认）/ `long`
  （详尽展开，含环境/心理/感官铺陈）
- 成稿消费 `nc-词频` 提供的词频向量作为约束输入，但词频工具本身不出正文

## 规则 24：研判/编排只出建议与计划，绝不静默改卡（v1.0 新增）

`nc-研判`(nc-analyze) 与 `nc-编排`(nc-compose) 是创作迭代分支工具，MUST 遵守：

- **研判只出报告**：`nc-研判` MUST 只输出结构化分析报告 + 方案 A/B/C（附利弊与
  连锁影响），绝不直接改动任何 cards/素材；报告末尾固定询问是否选定方案，作者
  确认后再调用对应专项技能（`nc-动向`/`nc-桥段`/`nc-感官标记` 等）落地变更。研判
  是操作技能，MUST NOT 生成独立驻留卡片（报告可选经 `nc-素材` 存入素材库）。
- **编排三段式**：`nc-编排` MUST 先生成结构化 compose_plan（create_plot / edit_plot /
  archive_plot / update_tendency / bind_sensory_cue 五类任务）交作者逐条审核
  （同意/编辑/移除/新增自定义任务/整体约束）；作者确认【计划定稿开始执行】后，
  执行前 MUST 前置跑一次 `nc-校阅` 扫描整套计划叠加后的冲突——无严重冲突则顺序
  执行（每步调底层技能 + 记 CHANGELOG + 更新 latest.md），遇红色冲突则暂停退回
  计划页让作者调整，绝不强行执行。计划文件 MUST 保存为素材（`tag:compose-plan`）
  便于回溯。全程禁止静默修改。
- **分工**：单点评估（少量资产、拿主意）走 `nc-研判`；批量整线迭代/扩写/重构
  （跨资产联动）走 `nc-编排`。两者都绝不静默改卡。详见 `references/skill-catalog.md`
  「技能职责不重叠原则」。

## 规则 25：更名先预览后替换且不动原始素材（v1.0 新增）

`nc-更名`(nc-rename) 专门处理**全局标识符替换**（项目主标题/故事书名，或角色代号 /
势力代号 / 核心道具代号），MUST 遵守：

- **先预览后写入**：MUST 先输出【替换预览清单】（列出每一处要修改的文件 + 原文
  片段），作者确认批准后才批量写入；自动在 history 生成本次变更快照、CHANGELOG
  追加记录、更新 latest.md。
- **不动原始素材**：MUST NOT 修改 `res/` 原始素材文件夹内内容（原始素材保留原样，
  只改卡片资产层）。
- **不动口语称呼**：MUST NOT 改动正文描写文本里的自然口语称呼（如文中「阿三」），
  只处理卡片注册的标识符。
- **内容修改走本体技能**：要改角色性格 / 暗线内容 / 桥段情节等**内容**（非改名）时，
  路由到对应本体技能（`nc-角色`/`nc-暗线`/`nc-桥段`/`nc-动向`），不走 `nc-更名`；
  一卡对应一修改入口保持内聚。归属工程维护类，非创作主线强制节点，
  `user_trigger_only`。

## 规则 26：动向每次变动必须绑定已存在桥段（v1.0 新增）

`character_tendency`（`tend-`）角色动向卡刻画角色性格/心智倾向的带触发事件连续滑动
标尺，MUST 遵守：

- **每次变动绑定桥段推手**：`history[]` 中每一条 MUST 绑定一个**已存在**的桥段卡
  （`trigger_plot` 引用真实 `pp-*` id）作为该次变动的推手事件，禁止无事件推手的
  凭空变性格。
- **依附角色不替代基础卡**：该卡 MUST 通过 `target_role` 引用 `ac-*` 角色 id，
  依附角色刻画其某条倾向维度；基线初始状态仍存于 `actor` 卡，`tend-` 卡只记录
  **变化过程**，MUST NOT 替代角色基础卡。
- **字段契约**：frontmatter 含 `target_role` / `dimension` / `baseline` /
  `direction_rule` / `current_value` / `history[]` / `notes`；`current_value` =
  `history[]` 最后一条的 value。`nc-检索` 支持 `type:character_tendency` 与按角色
  过滤；`nc-校阅` 可校验动向逻辑冲突（偏移无推手、方向与 direction_rule 矛盾等）。
  详见 `references/card-schema.md` character_tendency 节与 `templates/tendencies.md`。

## 违规响应模板

当 AI 检测到用户提供的卡片不符合硬规则时，**必须**：

1. **不直接修改**用户提供的原文
2. **在对话中指出违规点**，引用具体规则编号
3. **给出修正后的完整提案**，让用户对比决策

示例：

```
检测到违规：
- 规则 3：这是 `type: foreshadow` 卡片，缺少 `payoff_chapter`，
  也未标注 `status: unresolved`。合法组合有两种：
  a) 补 `status: unresolved`（若伏笔尚未回收）
  b) 补 `payoff_chapter: chapter-XX`（若已知回收章节）

建议提案（假设选 a）：
<完整卡片 Markdown>
```
