# 闭环工作流（Loop）

> 系统的形状：素材 → AI → 卡片 → 文章 → 读者反馈 / 自我复盘 → 新认知 →
> 再次口述素材 → 再次蒸馏卡片。
> 本文档描述三场景流程编排图、长短篇分级矩阵、写稿/审稿/修稿/定稿分支开关，
> 以及「文章 → 复盘 → 反哺 → 再写」这条回路的完整流程与硬约束。

> **面向对象透镜**：把每个流程节点读作一次对象方法调用——`nc-成稿` =
> `StoryWorld.export()` 的 render 阶段（按 timeline 顺序调各对象 `render()` 拼正文）、
> `nc-校阅` = `NcObject.validate()` + `StoryWorld.audit()`、`nc-研判` =
> `StoryWorld.deliberate()`、`nc-编排` = `StoryWorld.plan_modify()`（产出 ChangePlan）。
> 文字只是视图，真相在对象实例里；改剧情 = 改状态再重渲。完整类层次见
> `references/oo-model.md`，事件连锁推演见 `references/event-inference.md`。
> **OO 视角不改变任何流程节点与数值**，仅换叙述框架。

## 1. 为什么需要闭环

线性流程（素材→AI→卡片→文章）会退化成「用一次素材就耗尽」的一次性消费系统。
闭环系统的核心机制是：**每一篇文章都会被复盘，复盘结论被显式写回卡片/图谱，
下一篇文章继承上一篇文章的所有改进**。系统的复杂度是单调递增的，而不是每次
都从零开始。

## 2. 三场景流程编排图

v1.0 提供三种预设流程场景，由 `registry/work-length-config.yaml` 的 mode 决定默认
启用集；作者也可在 `agents.md` 自定义。

### 2.1 场景 A · 长篇深度打磨（long）

```
nc-初始化(long) → nc-素材 → [nc-清洗] → nc-检索
  → nc-角色/道具/场景/桥段/伏笔/势力/暗线/快照/积木/量化/动向
  → [nc-研判(单点推演分支)] / [nc-编排(批量迭代分支)]   ← 创作迭代分支，按需手动触发
  → nc-成稿(出正文初稿) + nc-词频(约束校验) → nc-校阅+nc-节奏(审稿) → 修稿
  → nc-定稿 → nc-导出
  → nc-复盘(反哺) → 回到 nc-素材/构思
```

> **OO 方法调用标注**：`nc-初始化`=`StoryWorld.constructor()`、`nc-素材`=`import_raw()`、
> `nc-检索`=`query()`、建卡各技能=`NcObject.create()/patch()`、`nc-研判`=`deliberate()`、
> `nc-编排`=`plan_modify()`、`nc-成稿`=`export()` 的 render 阶段、`nc-校阅`=`validate()+audit()`、
> `nc-定稿`=`snapshot()` 批量、`nc-导出`=`export()` 序列化落盘。

全技能开启：含 nc-伏笔 / nc-势力 / nc-暗线 / nc-量化 / nc-姿态 / nc-守卫 / nc-动向。
**写稿分工**：`nc-成稿`(nc-draft) 读全部卡片出正文初稿（内容生成），
`nc-词频`(nc-wordfreq) 提供词频向量 + 感官均衡约束（纯约束校验）。
**迭代分支**：`nc-研判`（单点推演，只出建议报告不改卡）与 `nc-编排`（批量三段式
计划→审核→执行）作为创作迭代分支工具，long 模式下全开但仍属「按需手动触发」，
不自动嵌入主线。

### 2.2 场景 B · 中篇标准流程（mid）

```
nc-初始化(mid) → nc-素材 → nc-检索
  → nc-角色/道具/场景/桥段/伏笔/积木/动向
  → [nc-研判/nc-编排(迭代分支，默认不主动推荐)]
  → nc-成稿(出初稿) + nc-词频(约束) → nc-校阅(审稿) → 修稿 → nc-定稿 → nc-导出
  → nc-复盘(反哺) → 回到构思
```

> **OO 方法调用标注**：与场景 A 同一套映射（`constructor()` / `import_raw()` / `query()` /
> `create()+patch()` / `deliberate()` / `plan_modify()` / `export()` render / `validate()+audit()`
> / `snapshot()`），仅启用的对象类型集合更小（关闭势力/暗线/量化/姿态）。

关闭：nc-势力 / nc-暗线 / nc-量化 / nc-姿态（按需手动开启）。
`nc-研判` / `nc-编排` 在 mid 下默认不主动推荐（作者需明确表达推演/批量意图才触发）。

### 2.3 场景 C · 短篇极简流程（short）

```
nc-初始化(short) → nc-素材
  → nc-角色/道具/场景/桥段
  → nc-成稿(--length short, 出精简初稿) + [nc-词频]
  → (跳过审稿/定稿) → nc-复盘(可选)
```

> **OO 方法调用标注**：`constructor()` / `import_raw()` / `create()+patch()`（仅基础对象类型）/
> `export()` render（`--length short`）。short 模式下 DarkLine / 长期 disposition_slide 等能力
> 关闭，事件连锁不跨越未启用对象类型（门控见 `references/event-inference.md` §5.3）。

关闭：nc-伏笔 / nc-势力 / nc-暗线 / nc-量化 / nc-对标 / nc-姿态 / nc-守卫 / nc-定稿 /
nc-校阅（全部默认关闭，作者可手动开启个别技能）。短篇 `nc-成稿` 用 `--length short`
产出精简骨架，`nc-词频` 可选。`nc-研判` / `nc-编排` 作为迭代分支工具在 short 下
默认不主动推荐（按需手动触发）。

### 3.1 角色动向弧光随桥段推进

`character_tendency`（`tend-`）卡刻画角色性格/心智倾向的**带触发事件的连续滑动
标尺**。其演进与桥段强耦合：每一次刻度变动 MUST 绑定一个具体桥段事件
（`trigger_plot` 引用 `pp-*`）作为推手，禁止凭空变性格。典型链路：

```
nc-动向(建 tend- 卡, baseline=0) → nc-桥段(新增 pp-* 事件)
  → [nc-研判(推演下一步刻度, 出方案 A/B/C)] → 作者选方案
  → nc-动向/nc-桥段(落地: history[] 追加 {value, trigger_plot, description})
  → [nc-编排(批量迭代计划, 跨多桥段联动偏移)] → 审核 → nc-校阅(扫冲突) → 执行
```

`nc-校阅` 会校验动向逻辑冲突（如某次偏移无对应桥段推手、或方向与 direction_rule
矛盾）；`nc-检索 type:character_tendency role:ac-*` 可拉取某角色全部动向标尺与变动
历史。基线初始状态仍存于 `actor` 卡，`tend-` 卡只记录**变化过程**，不替代角色基础卡。

## 4. 写稿 / 审稿 / 修稿 / 定稿分支开关

`registry/work-setting.yaml` 的 `pipeline_option` 控制后段流程分支：

```yaml
pipeline_option:
  enable_review: true      # 是否开启审稿（私人随笔/自娱直接 false 跳过）
  enable_finalize: true    # 是否开启定稿锁定（不发表就 false）
  enable_safety_guard: false  # 守卫默认关闭，需要时手动打开
```

### 4.1 写稿（nc-成稿 + nc-词频）

写稿环节拆为两个协作技能：

- **`nc-成稿`(nc-draft) — 出正文初稿**
  - 输入：章节/桥段 id + `--length short/mid/long`（篇幅档位）+ 已备好的全部卡片
    （设定 / 桥段 / 大纲 / 暗线 / 角色 / 道具 / 场景 / pose / lexstat 约束向量）
  - 输出：`manuscript/chapter-*.md` 正文初稿（**走提案制**，作者校阅调整后落盘）
  - 篇幅语义：`short` 精简骨架（约 1/3）/ `mid` 标准（默认）/ `long` 详尽展开
    （含环境 / 心理 / 感官铺陈）
- **`nc-词频`(nc-wordfreq) — 纯约束校验**
  - 输入：章节/桥段 id
  - 输出：`cards/lexstats/lx-*.md` 词频向量 + 感官均衡约束报告（**不出正文**）
  - 为 `nc-成稿` 提供约束输入；爆点段落高密词集中释放，爆点后强制留白，
    禁止持续堆叠感官描写

### 4.2 审稿（nc-校阅 + nc-节奏，受 `enable_review` 控制）

- `enable_review: false` → 跳过整个审稿环节，写稿后直接进入修稿或定稿
- `enable_review: true` → 执行 nc-校阅（设定/pose/动线/伏笔/动机/OOC 一致性）
  + nc-节奏（疏密/爆点密度/留白），产出意见书，**不改原文**
- 审计类技能铁律：只出意见，绝不自动修改文稿或卡片

### 4.3 修稿（作者手动）

- 根据审稿意见书，作者自行决定是否采纳并手动修改 manuscript / cards
- skill 不代改；若需重新生成某张卡，走对应 nc- 指令提案

### 4.4 定稿（nc-定稿，受 `enable_finalize` 控制）

- `enable_finalize: false` → 跳过快照归档，工程保持可编辑状态
- `enable_finalize: true` → 生成工程快照至 `history/`，追加 `CHANGELOG.md`，
  更新 `latest.md`，打上锁定标记

### 4.5 守卫（nc-守卫，受 `enable_safety_guard` 控制）

- 默认关闭；分发/发布前手动打开
- 隐私 + 合规内容扫描，区分【渲染加害红线】/【揭露批判疑点】，只告警不改文

## 5. 单章闭环流程

```
[写章]  →  manuscript/chapter-XXX.md 落盘
   ↓
[复盘]  →  nc-复盘 chapter-XXX 触发
   ↓
[反思卡]  reflections/<chapter-id>.md 草案 → 用户确认 → 落盘
   ↓
[反哺]  按 action_items 更新对应卡片 / 图谱 / 补素材
   ↓
[再写]  下一章写作时读到的卡片已包含上一章的所有新认知
```

## 6. 复盘触发时机

| 触发方式 | 说明 |
|---|---|
| 显式 | 用户在对话中说「nc-复盘 chapter-XXX」 |
| 建议 | 用户写完一章后 AI 主动提示「是否要对本章进行复盘？」 |
| 批量 | 写完 N 章后集中复盘，生成多张反思卡 |

**禁止**：AI 主动替用户写反思卡（违反提案制）。

## 7. 反哺规则

反思卡的 `action_items` 是**唯一**允许把新认知写回卡片的入口。
反哺动作必须遵循：

1. **可追踪**：每条 action_item 明确指向具体的卡 id 或图谱文件，不能是「优化一下人物刻画」这类模糊描述。
2. **原子**：一条 action_item 只对应一个卡片的一个具体修改点，便于用户逐条确认。
3. **不越权**：AI 只把 action_items 作为**建议**输出到对话；实际执行由用户逐条决定。
4. **可回滚**：每条 action_item 应描述「改成什么」而非「删除什么」，方便用户撤销。

## 8. 反哺回素材库

「反哺回素材库」有两层含义：

- **表层**：更新 `cards/` 下已有卡片（actor、plotpoint、item、scene、foreshadow、
  timeline、faction、snapshot、darklayer、module、lexstat、corpus、metric、pose、
  sensory_cue、refwork）。
- **深层**：如果新认知是**新素材**（一段口述、一个灵感），用户应在对话中直接口述，
  AI 按现有素材 → 卡片流程走一遍（先过**通胀过滤器 gate**，再决定是否入库）。

反哺回来的新素材**必须**先过 [filter.md](./filter.md) 描述的通胀过滤器
（现为 `nc-素材` 入库前自动 gate，亦可手动 `nc-过滤` 复检）。

## 9. 系统进化指标

一个健康的闭环系统，随时间应观察到：

- 反思卡数量 ≈ 已完稿章节数
- 卡片的 `updated` 时间戳持续刷新（说明认知在被反哺）
- 图谱节点/边的数量单调递增
- 后续章节引用历史反思卡的 `rf-` id 的频率上升

如果反思卡存在但卡片 `updated` 长期不变，说明反哺环节断了——复盘没落到卡片上。
