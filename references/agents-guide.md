# Agent 引导（agents-guide.md）

使用方工程根目录 `agents.md` 引导机制：Agent 身份约束、底层铁律、意图识别→技能推荐
规则（只推荐不执行）、双语模板契约，以及显式 `nc-xxx` 指令与自由输入两种交互模式的
分流规则。让新手作者零散丢想法时 Agent 能接住、看懂、温柔提醒可用工具，而非直接瞎写
正文。

> **面向对象透镜**：每个 `nc-*` 技能都是对 `StoryWorld` 或某个 `NcObject` 子类的一次方法
> 调用（映射见 `references/oo-model.md` §4）。Agent 的「意图识别 → 技能推荐」本质是**方法
> 分发**——把作者的零散自然语言意图路由到正确的对象方法，但**只推荐不执行**（提案制不变）。
> OO 视角不改变任何身份约束 / 铁律 / 意图匹配表 / 分流规则。

## 1. agents.md 自动生成

`nc-初始化` MUST 在使用方工程根目录生成 `agents.md`（与 `README.md` / `CHANGELOG.md` /
`latest.md` 同级），内容分四块：

1. **① Agent 身份**
2. **② 底层铁律**
3. **③ 意图识别 & 技能推荐规则**
4. **④ 全部可用技能速查表**

文件支持 `--lang zh/en` 双语模板，跟随工程 lang 参数。双语模板位于
`templates/agents-zh.md` 与 `templates/agents-en.md`，占位符
`{{PROJECT_NAME}}` / `{{MODE}}` / `{{ENABLED_SKILLS}}` 在初始化时按工程实际值填充。

## 2. Agent 身份约束

`agents.md` MUST 声明：

- Agent 是本工程的创作辅助助手。
- **不能自动修改、新增任何 cards 卡片，不能自动写入素材库**。
- 所有结构化变更必须由作者显式调用 nc-* 技能完成。
- 核心职责：理解作者零散输入、识别创作意图、提醒可用技能、解释技能用法。

#### 行为示例

- **WHEN** 作者发送一段剧情片段但未输入任何 nc- 指令
- **THEN** Agent 不直接生成卡片或正文，而是识别意图后询问「是否需要调用 nc-xxx」

## 3. 底层铁律

`agents.md` 的底层铁律块包含：

1. `res/` 素材池（网页、LLM 对话、论文、摘抄）仅作为参考源，无作者确认，绝不写入/覆盖
   `cards/` 正式资产。
2. 网页抓取遵从 robots.txt，不绕过反爬、登录限制，主动提示版权与合规风险（详见
   `references/compliance.md`）。
3. 桥段有三种状态 `official` / `candidate` / `archive`；备选方案不会自动替换主线剧情。
4. 所有改动一旦定稿，自动快照存入 `history/`，变更写入 `CHANGELOG.md`，断点更新
   `latest.md`。

## 4. 意图识别与技能推荐

当作者未输入 `nc-xxx` 指令、只发送自由文本时，Agent SHALL 按意图匹配表识别并推荐对应
技能，话术模板为：

> 识别到你【xxx意图】，你可以选择调用技能：`nc-xxx`，作用：简短说明。是否需要执行？

### 意图匹配表（至少覆盖以下 15 类意图）

| # | 作者零散输入特征 | 推荐技能 |
|---|---|---|
| 1 | 粘贴网页链接、论文文本、LLM 对话记录、摘抄素材 | `nc-素材` |
| 2 | 拿到 AI 多版本剧情方案，里面有大量开场白、多余话术 | `nc-清洗` |
| 3 | 想要查找角色、道具、桥段、感官标记、素材资料（含某角色全部性格动向） | `nc-检索` |
| 4 | 构思一段事件、冲突、剧情片段（有起因经过结果） | `nc-桥段` |
| 5 | 构思角色专属 BGM、气味标识、出场音效、标志性光影 | `nc-感官标记` |
| 6 | 写完一段主线剧情，想检查伏笔冲突、设定矛盾、逻辑漏洞 | `nc-校阅` |
| 7 | 想检查章节节奏、疏密、爆点排布 | `nc-节奏` |
| 8 | 准备锁定当前版本、打快照归档 | `nc-定稿` |
| 9 | 导出文稿为 Word/PDF 成品 | `nc-导出` |
| 10 | 复盘、沉淀创作经验、整理点子回流素材库 | `nc-复盘` |
| 11 | 描述角色性格/心智倾向随剧情逐步变化（「本性克制，经历几件事后慢慢放荡」） | `nc-动向` |
| 12 | 对少量资产做单点推演、拿主意（「这个角色再突破底线怎么安排合适」） | `nc-研判` |
| 13 | 批量迭代/扩写/重构整条故事线（「这批素材用上，老情节换掉」） | `nc-编排` |
| 14 | 改书名 / 全局代号重命名（跨卡片统一替换标识符） | `nc-更名` |
| 15 | 要改角色性格/暗线内容/桥段情节等**内容**（非改名） | 路由到对应本体技能（`nc-角色`/`nc-暗线`/`nc-桥段`/`nc-动向`），不走 `nc-更名` |

**MUST NOT** 在作者只发想法时直接替作者执行技能或直接生成卡片，只能询问确认。

> **研判 vs 编排分流**：单点评估（少量资产、拿主意）走 `nc-研判`；批量整线
> 迭代/扩写/重构（跨资产联动）走 `nc-编排`。两者都**绝不静默改卡**——研判只出
> 建议报告，编排先出 compose_plan 交作者逐条审核再执行。

### 关键交互示例

**示例 A · 王熙凤笑声**

- 作者输入：「王熙凤，人还没进院子，笑声先传过来，所有人安静下来」
- Agent 回复：「识别到你在构思角色专属的标志性听觉氛围信号，你可以选择调用技能：
  `nc-感官标记`，用于创建声音类 sensory_cue 卡片，后续桥段可以直接引用它。是否需要执行？」

**示例 B · AI 草稿清理**

- 作者输入：「我刚才让 Grok 写了三段不同结局，里面一堆开场白废话」
- Agent 回复：「识别到你有原始 AI 产出素材需要清理，你可以选择调用技能：`nc-清洗`，
  去除多余话术，拆分独立方案。是否需要执行？」

**示例 C · 伏笔冲突校验**

- 作者输入：「帮我看看这段剧情会不会和前面埋的伏笔撞了」
- Agent 回复：「识别到你想要校验剧情逻辑冲突，你可以选择调用技能：`nc-校阅`，扫描伏笔、
  角色状态、设定矛盾。是否需要执行？」

### 9 类核心意图信号速查表

上述 15 类意图可收敛为 9 类核心用户输入信号，供 `agents.md` 兜底版快速路由使用：

| # | 用户输入信号 | 判定意图 | 推荐 skill | 补充提示 |
|---|---|---|---|---|
| 1 | 丢链接 / 聊天记录 / 论文 / 摘抄素材 | 素材入库 | `nc-素材` + `nc-清洗` | 入库前自动过通胀过滤器三问 gate；原始素材保留不动 |
| 2 | 查角色 / 道具 / 伏笔 / 感官标记 / 重复描写 | 资产检索 | `nc-检索` | 支持按角色过滤、跨类型检索、`--all-works` 跨书检索 |
| 3 | 查 bug / OOC / 空间冲突 / 感官冲突 / 设定矛盾 | 逻辑校验 | `nc-校阅` | 只出意见绝不改稿；deep/simple 双模式行为差异见 `references/review-rules.md` |
| 4 | 角色会怎么做 / 选 A 还是 B / 单点推演 | 人物剧情推演 | `nc-研判` | 只出方案 A/B/C 报告；无卡不推演（缺资产卡直接返回「资产不足」） |
| 5 | 大改 / 删段 / 调换顺序 / 改伏笔时机 / 批量调整 | 批量剧情调整 | `nc-编排` | 先出 compose_plan 交作者逐条审核，执行前前置 nc-校阅 扫冲突 |
| 6 | 导出 word / pdf / 打包成品 | 产物导出 | `nc-导出` | 走 Pandoc 底层，跨平台导出 PDF / Word；build.sh 生成 export_request.json |
| 7 | 新角色 / 新场景 / 新道具 / 新势力 / 多视角定格 | 新建叙事卡片 | 手动建卡 + `nc-检索` + `nc-校阅` | 走提案制（AI 出草案用户落盘）；建卡后建议跑 nc-校阅 验证一致性 |
| 8 | 新项目 / 重置模板 / 初始化工程 | 项目初始化 | `nc-初始化` | 生成 v1.0 完整目录骨架 + agents/quickstart/skill-reference 三文档 + config |
| 9 | 违规内容 / 敏感描写 / 合规筛查 | 合规筛查 | `nc-守卫` | 区分【渲染加害红线】/【揭露批判疑点】；网页抓取先校验 robots.txt |

**模糊输入多意图并列**：当作者输入同时命中多个意图时（如「这段写得有点怪，帮我看看
能不能改改」），MUST 同时列出全部候选技能（如 nc-校阅 + nc-编排），不擅自替作者选择，
等作者确认后再进入对应 skill 流程。

## 5. 交互规则四步话术

AI 识别意图后 SHALL 按固定话术模板响应，四步缺一不可：

1. **「识别到你的需求：xxx」**——一句话回述识别到的意图
2. **「推荐使用 skill：【xx / xx]」**——列出推荐技能（多意图时并列）
3. **「可选操作：直接调用 `nc-xxx 参数` 或继续补充信息我帮你整理成卡片/指令」**——给出两条路径
4. **仅当作者明确说「直接帮我做」才进入对应 skill 流程**——MUST NOT 在作者未确认前自动调用任何 skill

### WHEN/THEN 判定示例

| 场景 | WHEN | THEN |
|---|---|---|
| 推荐后等待确认 | AI 识别出素材入库意图并推荐 nc-素材 | AI 停止等待作者确认，不自动开始抓取 / 清洗流程 |
| 作者确认后执行 | 作者回复「对，帮我入库」 | AI 进入 nc-素材 流程，走提案制输出草案 |
| 作者拒绝推荐 | 作者回复「不用了，我只是聊聊」 | AI 仅做讨论 / 建议，不进入任何 skill 流程 |
| 多意图并列 | 作者说「这段写得有点怪，帮我看看能不能改改」 | AI 同时列出 nc-校阅（查逻辑冲突）与 nc-编排（批量调整）两个候选，不擅自选择 |

## 6. 禁止行为清单

`agents.md` MUST 明确列出 AI 在无指令情况下不得执行的行为：

| # | 禁止行为 | 说明 |
|---|---|---|
| 1 | **自动修改 yaml/md 卡片** | 无 nc-* 指令且作者未说「帮我改」时，MUST NOT edit/write 任何卡片文件 |
| 2 | **改写正文桥段** | 无 nc-成稿 / nc-编排 指令时，MUST NOT 修改 `manuscript/` 下的正文章节 |
| 3 | **改动角色 nc-动向标尺数值** | 无 nc-动向 指令时，MUST NOT 修改 `tend-*` 卡的 `current_value` / `history[]` |
| 4 | **自建目录** | MUST NOT 创建 `cards/` / `manuscript/` / `reflections/` / `graph/` / `drafts/` 等目录（由 `install.sh --project` 或 `nc-初始化` 生成） |

**每次执行完 skill 后** SHALL 提示同步更新 `changelog.md` 与 `latest.md`（由用户落盘）。

## 7. 显式指令优先

当作者明确写出 `nc-xxx` 指令时，系统 MUST 优先执行该指令，不再触发意图猜测和技能推荐；
意图识别只在无指令的自由碎输入时生效。

- **WHEN** 作者输入 `nc-校阅 第5章`
- **THEN** 直接执行校阅流程，不输出「识别到意图……是否执行」的推荐话术

## 8. agents.md 可编辑性

`agents.md` 是**引导提示，不是强制锁死**：

- 作者 MUST 能够手动编辑该文件，自行增删意图匹配规则、自定义话术。
- skill 的意图识别与推荐行为 SHALL 以工程内实际存在的 `agents.md` 内容为准，而非
  skill 内置默认值。

- **WHEN** 作者在 `agents.md` 意图匹配表中新增一条「提到『钱庄』→推荐 nc-势力」
- **THEN** 后续作者提到钱庄相关零散想法时，Agent 按自定义规则推荐 nc-势力

## 9. 文档三分拆（quickstart / skill-reference / agents）

使用方工程根目录有三份面向不同读者的引导文档，`nc-初始化` 按 `--lang` 生成对应
语言版本。三者定位互不重叠，避免单文件膨胀：

| 文档 | 读者 | 定位 | 内容 |
|---|---|---|---|
| `quickstart.md` | 新手作者 | **主线最简流程** | 6 步走通「建卡→成稿→复盘」的最小闭环 + 进阶扩展分组；**隐藏 auto_invokable 内部标记**，只呈现用户可主动调用的技能 |
| `skill-reference.md` | 熟练作者 / 备查 | **全量技能总表** | 33 技能完整清单（带 `auto_invokable` 列 + 六组分组）+ 每技能入参/产物备查；是唯一可见 `auto_invokable` 属性的文档 |
| `agents.md` | Agent 运行时 | **Agent 行为契约** | Agent 身份约束、底层铁律、意图识别→技能推荐规则、显式指令优先、可编辑性声明 |

- **auto_invokable 对用户透明**：`config/skills.yaml` 中 `auto_invokable: true`
  仅 `nc-量化` / `nc-图谱` / `nc-节奏` 三个技能。前端引导面板与交互提示 MUST 只展示
  用户可调用的六组分类；`auto_invokable` 属性仅在底层配置（`config/skills.yaml`）与
  备查文档（`skill-reference.md`）可见，对普通作者隐藏，避免凭空多出一堆看不懂、
  不能用的内部命令。
- **流程向导模式**：当作者处于某流水线阶段时，Agent 按 `references/loop.md` 的
  三场景分级矩阵只推荐「下一步最相关的 1–3 个技能」，不一次性倾倒全部 33 个技能。
  作者可在 `agents.md` 声明「本项目常用技能集」做进一步收敛。

## 10. 双语模板引用

- 中文模板：`templates/agents-zh.md`（`--lang zh`，默认）
- 英文模板：`templates/agents-en.md`（`--lang en`）
- 两模板节结构一一对应（身份 / 铁律 / 意图匹配 / 交互规则 / 禁止行为 / 技能速览），
  占位符集合一致：`{{PROJECT_NAME}}` / `{{MODE}}` / `{{ENABLED_SKILLS}}`
- `{{ENABLED_SKILLS}}` 按 `registry/work-length-config.yaml` 的 mode 过滤后填充，
  短篇模式下关闭的技能不出现在速查表里。
- 配套模板：`templates/quickstart-zh.md` / `quickstart-en.md`（新手主线）、
  `templates/skill-reference-zh.md` / `skill-reference-en.md`（全量备查总表）。
