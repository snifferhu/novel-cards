# 暗线-甲

> **语义（v1.0）**：暗线**不是仅指代角色**。它是「整条明面叙事中没有明说、
> 需要读者自行推敲的隐性逻辑」——可以是隐秘设定、桥段背后的真实因果、角色的
> 隐藏动机链，或多种混合。判断标准：读者读完全文回看能发现「原来如此」的那条
> 暗逻辑。（hard-rules.md 规则 22）
>
> **硬规则**：暗线卡必须位于 `cards/darklayer/`（或等价独立命名空间）。
> `id` 必须以 `dk-` 开头，**不得**与主书角色链（`ac-*`）共享前缀或命名空间。
> 与主书对象的引用**只**通过 `references_to_main` 显式串接，可混合多类前缀
> （`ac-` 角色 / `pp-` 桥段 / `it-` 道具 / `fa-` 势力 / `sc-` 场景），不隐式合并。
> 在 `index/card-graph.json` 图森林中，暗线节点归属本工程的 `tree_id`
> （单主线为 `main`），但 MUST NOT 被主书卡反向链接（hard-rules.md 规则 4）。

## 一句话

<这条暗线的核心内容 / 主题——它到底是哪一类隐性逻辑（设定？桥段因果？角色动机？）。>

## 隐性逻辑类型（implicit_kind）

- `setting` — 一条贯穿全书的隐秘设定（世界观真相 / 规则内幕）
- `plot` — 一组桥段背后的真实因果（表面事件 A，实为 B 推动）
- `character` — 某个角色的隐藏动机链 / 真实身份
- `mixed` — 以上混合（默认；多数长线暗线属此类）

## 层级

`layer` 取值范围 1-7，对应"七层暗线"结构：

- **1** — 表层暗线：读者可察觉的悬念
- **2-3** — 中层：世界观 / 政治 / 组织层面的暗流
- **4-5** — 深层：人物身份 / 血脉 / 命运层面的伏笔
- **6-7** — 底层：核心主题 / 命运 / 元叙事

## 与主书对象的显式引用（多类混合）

`references_to_main` 是显式的、可枚举的引用列表，可混合多类主书对象前缀
（`ac-` 角色 / `pp-` 桥段 / `it-` 道具 / `fa-` 势力 / `sc-` 场景）：

```yaml
references_to_main:
  # 角色类隐性路线
  - ac-<slug>: <该角色在暗线中的真实动机 / 隐藏身份>
  # 桥段类隐性路线（表面事件背后的真实因果）
  - pp-<slug>: <此桥段实际由暗线推动，表面看是 X，实为 Y>
  # 设定类隐性路线（隐秘世界观规则）
  - sc-<slug>: <该场景中埋藏的设定暗示点>
  # 道具 / 势力类（按需）
  - it-<slug>: <道具在暗线中的真实作用>
  - fa-<slug>: <势力在暗线中的真实立场>
```

**不要**在这里写入主书卡的完整内容 —— 只在暗线卡中记录
"这个暗线逻辑在主书里通过哪些对象、以什么方式暗示"。
