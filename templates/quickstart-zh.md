## 获取与安装（首次落地）

若你刚拿到 novel-cards，按四步走通「获取 → 放置 → 安装 → 落地首卡」：

1. **获取**：`git clone https://github.com/snifferhu/novel-cards.git`（跟更推荐），
   或下载 release 归档包（一次性快照，升级需重新下载）。
2. **放置**：克隆 / 解压目录放任意位置即可——`install.sh` 以脚本所在目录为源码根，
   无固定路径依赖（`--link` 软链模式须长期保留源目录）。
3. **安装**：`./install.sh`（装到全局 OpenCode + Claude Code）/ `--target opencode|claude`
   （单端）/ `--link`（开发期软链）。装后在 agent skills 面板确认 `novel-cards` 可见。
4. **落地**：`./install.sh --project <path>` 生成骨架 → 进入该目录跑 `nc-初始化` →
   第一条 `nc-角色` / `nc-桥段` 指令建出第一张卡（即下方主线第 1–2 步）。

## 主线六步（最小闭环）

走通「建卡 → 成稿 → 复盘」的最小创作闭环，只需以下六步：

| 步骤 | 做什么 | 调用技能 | 产物 |
|---|---|---|---|
| 1 | 收纳入手素材（口述灵感 / 粘贴文本 / 网页摘抄） | `nc-素材` | `res/inbox/` + 语料卡 |
| 2 | 建核心卡片：角色 / 道具 / 场景 / 桥段 | `nc-角色` / `nc-道具` / `nc-场景` / `nc-桥段` | `cards/` 下各类型卡 |
| 3 | （可选）给关键桥段绑积木模块，组装触发关系 | `nc-积木` | `cards/modules/md-*.md` |
| 4 | 出正文初稿（按篇幅档位） | `nc-成稿 --length short/mid/long` | `manuscript/chapter-*.md` 提案 |
| 5 | 校阅调整（设定一致性 / 节奏 / 伏笔冲突） | `nc-校阅`（内置 `nc-节奏`） | 审计意见书（只出建议） |
| 6 | 沉淀经验、回流素材库，开启下一轮构思 | `nc-复盘` | `reflections/rf-*.md` |

> **提案制**：以上每一步 AI 都只输出完整 Markdown 提案到对话，**你确认后自行落盘**；
> AI 绝不直接写卡 / 写正文。

## 进阶扩展（按需启用）

主线跑顺后，可按需解锁以下能力（均支持中文 + 英文别名调用）：

### 叙事建模增强

- `nc-动向` — 刻画角色性格/心智倾向的滑动标尺（每次变动绑定具体桥段推手）
- `nc-姿态` — 角色招牌动作库（内核 + 环境插槽 + 多视角模板）
- `nc-感官标记` — 声音/气味/光影等标志性氛围信号
- `nc-伏笔` — 长线伏笔预埋与回收登记（短篇默认关闭）
- `nc-快照` — 时间锚点全局状态切片（长篇群像优先）
- `nc-势力` / `nc-暗线` — 多方势力网络 / 隐秘叙事链路（长篇默认开启）

### 创作迭代分支

- `nc-研判` — 对少量资产做单点推演，出方案 A/B/C（**只出建议报告，不改卡**）
- `nc-编排` — 批量迭代/扩写/重构整条故事线（**先出计划交你审核再执行**）

### 深度打磨与校验

- `nc-量化` — 张力/爆点/信息载荷量化指标
- `nc-词频` — 词频向量 + 感官均衡约束（配合成稿）
- `nc-图谱` — 渲染叙事森林时序图 / 关系图 / 动线链路图
- `nc-守卫` — 隐私 + 合规内容扫描（分发前使用）

### 书内谱系管理（长篇卷章结构）

- **定位**：管理一本书的卷 / 章节 / 配套物料（梗概 / 宣发 / 角色卡 / 草稿 / 测试 / 参考）
  时序与从属关系，逻辑真值存于 `index.yaml`（由技能自动维护），物理文件走浅目录
  （`MAI/ABR/PRO/CAR/DRF/TST/REF` 七类子目录，≤1 层）。
- `nc-谱系新增` — 新增卷 / 章节 / 配套物料并登记进 `index.yaml`；`--exist-file` 挂靠已有 md。
- `nc-谱系修改` — 改标题 / 调时序（follow）/ 变更归属 / 改状态；默认只改索引不动文件名。
- `nc-谱系移除` — 默认软删除（`archived: true`，文件保留可恢复）；`--hard` 硬删除需二次确认。
- `nc-谱系查询` — 查整 IP 谱系树 / 单卷带章节 + 前后置；输出文字谱系树。
- 完整契约见 skill 仓库 `references/lineage.md`；存量工程无 `index.yaml` 时视为未启用，行为不变。

### 归档导出与维护

- `nc-定稿` — 工程快照归档、打锁定标记
- `nc-导出` — 跨平台导出 PDF / Word
- `nc-更名` — 改书名 / 全局代号重命名（**先预览后替换，不动原始素材**）
- `nc-检索` / `nc-清洗` / `nc-注册` — 检索资产 / 素材降噪 / 注册自定义类型

## 多本作品与署名（同项目）

一个工程可同时管理多本书：每本是 `works/<work-id>/` 独立子空间，数据互不串卡。

- **再开一本**：`nc-初始化 --new-work`（在既有工程内追加，不另起工程）。
- **限定作用域**：任意 `nc-*` 技能加 `--work <work-id>`；缺省按「显式 → active_work →
  唯一书 → 否则提示」解析，绝不静默猜错书。
- **跨书检索 / 总览**：`nc-检索 --all-works`（结果带 work-id 归属）或查询「本工程有哪些书」。
- **多笔名署名**：`nc-注册` 登记笔名到 `registry/pen-names.yaml`；每本设 `default_pen_name`，
  单章可用 frontmatter `pen_name` 覆写；`nc-导出` / `nc-成稿` 按生效笔名落款。
- **老项目接入**：已有内容的工程先跑 `nc-初始化` 出迁移规划表再归位——skill 扫描工作空间、
  逐目录给出「源路径 / 建议目标目录 / 建议 type·id 前缀 / 处置动作」四列表交你确认；历史设定 /
  章节规划等无法直接转写的进 `res/inbox/` 待清洗（后续走 `nc-清洗` / `nc-素材`）。skill 只在
  归位后接管，绝不自动移动 / 改写你的存量文件。
- 单本工程（无 `works[]`）行为与引入前完全一致。

## 双模式剖面（simple / deep）

校验松紧度与长短篇 mode 正交，由 `config/project.yaml` 的 `world_base_profile` 控制：

- **simple**（缺省）：nc-校阅 / nc-研判 / nc-编排 只拦 L1 硬错（感官权限冲突 / 空间穿墙 /
  因果断裂），适合爽文快节奏创作。
- **deep**：全链路严格校验（感官通道 + 前庭觉 + 内感受 + 激素互斥 + 感知缺陷 + 空间物理 +
  性格滑动），适合深度写实推演。
- **单卡覆写**：某张桥段 / 快照卡 frontmatter 加 `profile_override: simple|deep` 可局部切换，
  仅作用于该卡及其直接关联资产。
- 存量工程缺 `world_base_profile` 字段时按隐式 simple 处理，行为不变、不报错。
