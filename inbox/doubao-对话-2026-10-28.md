## 三、双轨制：索引表承担 “记忆层级” 的工作（核心，解决你最大的麻烦）

```
# 软删除：索引标记 archived，文件保留，不再出现在正常谱系树，可恢复
nc-lineage-del --ip SHZ --id SHZ-MAI-001-CH07
# 硬删除：索引删掉 + 本地文件直接删除（高危，需要二次确认）
nc-lineage-del --ip SHZ --id SHZ-MAI-001-CH07 --hard
# 恢复软删除条目
nc-lineage-add --restore SHZ-MAI-001-CH07
```

✅ 自动行为：
软删除只是加字段 `archived: true`，检索谱系时默认过滤归档条目；查询归档可以加参数 `--show-archived`。

# 查单卷，带出它所有章节、前置后置
nc-lineage-query --ip SHZ --id SHZ-MAI-001

## 四、两种核心场景落地（新建文章 / 已有文章挂靠）

### 场景 A：新建文章（从零生成）

```
nc-lineage-add --ip SHZ --type MAI --vol 001 --ch 06 --title "第六章 山道伏击"
```

1. 校验编号不冲突
2. 自动生成 `SHZ/MAI/SHZ-MAI-001-CH06.md`
3. 自动登记进 SHZ/index.yaml，归属卷 001
4. CHANGELOG 记录变更
5. 可以直接调用 nc - 校阅、nc - 编排

### 场景 B：本地已经写好的 md，快速挂靠进谱系（你的重点需求）

假设你已经手动写完：`SHZ/MAI/SHZ-MAI-001-CH06.md`
执行：

```
nc-lineage-add --ip SHZ --type MAI --vol 001 --ch 06 --title "第六章 山道伏击" --exist-file ./MAI/SHZ-MAI-001-CH06.md
```

👉 **不会新建文件，只在索引库里面登记它的从属、时序、标题**，瞬间纳入谱系管理，后续查询、溯源、联动校阅都生效。

> 
> 兜底：如果文件名不遵守规范，Skill 会提示警告，问你要不要自动重命名对齐规范。

## 五、索引 yaml 字段样例（SHZ/index.yaml）

```
ip_id: SHZ
ip_name: 山河志
status: writing
lineage:
  - uid: SHZ-MAI-001
    type: MAI
    vol: "001"
    title: "卷一 风起荒原"
    follow: null
    status: writing
    archived: false
    children:
      - SHZ-MAI-001-CH01
      - SHZ-MAI-001-CH02
      - SHZ-MAI-001-CH05
  - uid: SHZ-MAI-001-CH05
    type: MAI
    vol: "001"
    ch: "05"
    title: "第五章 雨夜渡口相逢"
    file_path: "./MAI/SHZ-MAI-001-CH05.md"
    archived: false
related:
  abr: [ "SHZ-ABR-V01" ]
  promo: [ "SHZ-PRO-S10", "SHZ-PRO-S30", "SHZ-PRO-M01", "SHZ-PRO-M05" ]
```

`uid` 是全局唯一主键，所有 nc-lineage 操作都靠 uid 定位，不依赖路径。

## 六、边界约束（防止体系崩坏）

1. 物理目录：IP 根下最多一层子文件夹，禁止嵌套更深
2. 时序关系只写在 `follow` 字段，不靠文件夹顺序定义剧情先后
3. uid 严格遵循 `IP-3位码-编号` 格式，全局唯一
4. 人优先用 nc-lineage-* 指令，**不推荐直接手改 index.yaml**；如果手动改坏，后续 query 会报错，附带校验能力
5. 改名分离：逻辑改名（标题）随时改；文件名改名需要显式参数，避免批量连锁错乱

## 七、和现有整套 NAVI CARDS 联动

- nc - 检索 (nc-query)：命中素材卡片
- nc-lineage-query：命中作品时序谱系
- nc - 编排：可以读取谱系，按顺序批量生成下一章、梗概、宣发稿，自动挂靠谱系
- nc - 校阅：支持传入 uid，限定只校验这一卷 / 这一章，自动读取它前置卷的设定，做一致性校验
