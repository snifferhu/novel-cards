### 定名：`nc-动向`（英文 `nc-tendency`）

资产类型：`character_tendency` 角色动向卡片

> 
> 你这个想法的核心：
> 角色性格不是静态写死在角色卡上的固定值，是**带触发事件的连续滑动标尺**；有基准、有方向、有触发节点、有当前刻度，每次变动都绑定具体剧情事件，不是凭空变性格。
> 
> 
> 例子：标尺方向固定（逐步向放荡偏移），每一次滑动，背后都对应一个桥段、一个事件作为推手。

## 和已有卡片区分清楚

- `role` 角色基础卡：存**基线初始状态**（初始性格、基础设定），是标尺起点，不再写一大段 “固定性格”。
- `plot` 桥段：发生的事件本身。
- `sensory_cue`：感官氛围标记（声音、气味、BGM）。
- `character_tendency`【动向卡片】：**性格 / 心智倾向的变化轨迹、标尺、触发记录**。
✅ 它依附角色，引用桥段作为变动原因；
✅ 它记录：维度、滑动方向、刻度、触发事件 ID；
✅ `nc-校阅` 可以校验：动向是否前后自洽、有没有违背已经记录的触发逻辑。

### 示例 yaml 卡片

```
id: tend_001
type: character_tendency
target_role: role_002  # 绑定角色ID
dimension: 克制 ↔ 放荡
baseline: 0            # 初始基线刻度（角色刚出场的值）
direction_rule: 整体长期倾向向放荡滑动（不强制每一次都向右，只是长期趋势）
current_value: +2
history:
  - value: +1
    trigger_plot: plot_041
    description: 当众违背礼教，接受陌生馈赠
  - value: +2
    trigger_plot: plot_067
    description: 主动放弃婚约，拒绝家族安排
notes: 不是一次性突变；每一次变动必须绑定已存在的桥段；允许短期小幅回弹，但主线趋势不变
```

> 
> 重点：
> `direction_rule` = 你说的「滑动的方向始终一致」；
> history 数组 = 「每一步都有具体的触发事件」。

# 新增技能：nc - 研判（nc-analyze）

定位：**AI 分析、给出改动建议，但绝不自动修改卡片；全部改动必须等作者确认后，再调用对应技能执行**

> 
> 和 nc - 校阅 做明确区分：
> 
> 
> - nc - 校阅：偏向【规则校验、查冲突、查漏洞】（偏 “找茬”，客观检查设定、伏笔、动向、感官标记之间矛盾）
> - nc - 研判：偏向【创作层面的推演、方案建议、多版本推演、人物走向推演】（偏 “出主意”，主观创作建议）

## 核心规则

1. 输入：指定资产（桥段 / 角色动向 / 感官标记 / 角色卡等，可多个一起）+ 作者的诉求
2. 输出：结构化分析 + 可选修改方案 A/B/C，附带每个方案的利弊、对其他资产的连锁影响
3. 铁律：**只输出建议报告，不直接改动任何 cards、素材**；报告末尾固定询问：是否选定方案，确认后调用对应技能执行修改
4. 可以联动其他资产：分析时自动拉取关联的 `character_tendency`（动向标尺）、sensory_cue、伏笔快照一起参考
5. 支持的分析方向示例：
   - 人物动向推演：按当前标尺，下一个触发事件给到之后，角色刻度会怎么变、是否符合长期趋势
   - 剧情分支推演：这段桥段改了，会影响哪些伏笔、后续角色动向、感官标记氛围
   - 氛围匹配检查：当前桥段搭配这个 sensory_cue，情绪是否协调，备选感官标记推荐
   - 人物一致性建议：角色行为和当前动向刻度是否匹配，给出调整方案
   - 节奏评估：配合 nc-rhythm，给出疏密调整建议

# 新增技能：nc - 编排（nc-compose）

> 
> 定位：**批量剧情编排、文稿组装、桥段联动更新技能**
> 核心铁律：**绝不直接改动任何 cards、正文成品**。先输出一份结构化【编排执行计划】给作者；作者审核、增删、修改计划、标记确认放行之后，内核才会按照定稿后的计划，依次调用对应技能（nc - 桥段 /nc - 动向 /nc - 感官标记 /nc - 素材）落地变更。
> 和 nc - 研判 的区别：
> 
> 
> - nc - 研判：少量资产、单点推演，给多方案选择，偏向局部微调评估
> - nc - 编排：大批量、跨资产联动，根据素材、新增桥段、情节改动，生成一整套连贯修改清单（可以一次性更新多个桥段、多条角色动向、挂载 / 更换感官标记），偏向整条故事线的迭代、扩写、重构

## 一、适用场景（就是你说的场景）

素材库已经积累大量素材，现在新增一段情节 / 改动原有剧情走向，需要：

1. 读取关联素材、现有桥段、角色动向标尺、感官标记
2. 自动梳理：哪些桥段要新增、哪些要修改、哪些归档（archive）、哪些角色动向刻度需要滑动、哪些 sensory_cue 需要新增 / 解绑 / 绑定
3. 整理成**可逐条审核的计划清单**
4. 作者逐条：同意 / 修改这条任务 / 拒绝删除这条任务，调整完整份计划
5. 作者确认【计划定稿，开始执行】→ 内核按顺序执行计划里的每一条变更动作，每一步动作依然保留日志、写入 CHANGELOG、更新 latest.md；执行中遇到冲突会暂停，触发 nc - 校阅告警等待人工处理

## 二、nc-compose 输入参数

```
nc-编排
--source [素材ID列表 / 素材检索条件]    # 用到的新素材
--reference [参考桥段/角色/动向ID列表]  # 原有相关资产
--prompt [情节变更目标描述]            # 作者：新增剧情、改动方向、核心约束
--mode [expand / rewrite / restructure]
# expand 扩写：在现有主线基础上追加新情节
# rewrite 改写：替换某一段剧情
# restructure 重构：重组多条桥段顺序、调整时序
```

计划固定分为 4 大类任务，每一条任务自带：任务 ID、类型、目标资产 ID、变更说明、预期影响、风险提示

## 四、审核流程（GUI 交互，也支持 CLI）

1. 生成计划后，进入审核面板：
   - 每一条任务：预览内容
   - 操作按钮：✅同意 / ✏️编辑任务（直接修改这条的参数、文本、刻度） / ❌移除这条任务
2. 作者可以新增自定义任务（手动追加一条修改）
3. 作者可以整体添加约束：比如【禁止大幅度跳动角色刻度，单次变动最多 + 1】
4. 作者点击【计划审核完成，提交执行】
5. 执行前自动跑一次 nc - 校阅，扫描整套计划全部任务叠加之后会不会产生冲突
   - 无严重冲突：顺序逐条执行任务，每一条动作调用对应的底层技能（nc - 桥段 /nc - 动向 …），每一步都记录 CHANGELOG
   - 存在红色冲突：暂停，弹出冲突位置，退回计划页面让作者调整计划，不会强行执行

> 
> 执行过程中，每一条任务执行完成，会生成一条变更记录；中途随时可以【暂停执行】。

# 新增 Skill：nc - 更名（nc-rename）

加入整套体系，同步更新 spec、总表、流程、yaml、quickstart、skill-reference

## 定位说明

- 原有逻辑：修改角色、道具、桥段、暗线、快照这类**叙事卡片内容**，走对应本体 skill（nc - 角色 /nc - 暗线 /nc - 桥段……），即：`nc-角色` 本身就支持更新修改角色卡、`nc-暗线` 支持修改暗线记录，不需要单独再做一个通用 “修改 skill”，**一卡对应一修改入口**，保持内聚。
- 单独新增 `nc-更名(nc-rename)`：专门处理**全局标识符替换**，最典型场景：故事总标题变更；也支持批量别名、势力代号、角色代号全局重命名（跨所有卡片、伏笔、快照、桥段、图谱引用统一替换）。

> 
> 区分边界：
> 
> 
> 1. 改角色性格、改暗线内容、改桥段情节 → `nc-角色` / `nc-暗线` / `nc-桥段`（本体 skill 自带编辑更新能力）
> 2. 改【对外 / 全局唯一名字】，需要全工程批量替换所有引用（书名、角色代号、势力代号、核心道具代号）→ **nc-rename**

## nc - 更名（nc-rename）参数与行为

```
调用别名：nc-更名 / nc-rename
归属分组：工程初始化 & 素材资产组
auto_invokable: false（只能作者主动调用，不会别的skill自动跑）
```

职责：

1. 支持修改**项目主标题（故事书名）**：更新根 README、project.yaml、CHANGELOG、latest.md，所有导出模板（word/pdf 页眉标题）同步更新；
2. 可选模式：全局代号重命名
   - 源名称：旧标识
   - 新名称：替换后的标识
   - 扫描范围：cards 下全部卡片、积木、伏笔、快照、暗线、桥段内的引用
3. **安全机制（关键）**
   - 先输出【替换预览清单】，列出每一处要修改的文件 + 原文片段；
   - 作者确认批准之后，才批量写入；
   - 自动在 history 生成本次变更快照，CHANGELOG 追加记录，更新 latest.md；
   - 不自动修改 res 素材文件夹内原始素材（原始素材保留原样，只修改卡片资产层，防止破坏原始史料 / LLM 对话素材）；
4. 不改动正文描写文本里的自然称呼（比如文中 “阿三” 这种口语称呼，只处理**卡片注册的标识符**，避免误伤正文）。
